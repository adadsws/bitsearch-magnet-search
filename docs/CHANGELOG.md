## 2026-11-02

- 搜索页改为独立的本地筛选、Bitsearch API 条件、搜索与补充、结果区块；搜索/清空与当前页批量补充分组，已生效条件集中在操作区，未搜索时隐藏空结果概览。
- Torrent 补齐成功卡片放大标题、数据、文件大小与卡片高度；失败卡片缩小文字和高度，便于快速辨认。
- Torrent 批量补齐成功的结果卡片、逐文件大小和完成数量突出显示；元数据文件表作为逐文件大小的完整来源，API 路径仅在唯一匹配时用于显示，修复 Torrent 根目录与 API 相对路径不同导致的重复。
- Torrent 下载只接受已知缓存站的同一 infohash 地址；跳转广告页或返回 HTML 视为未收录并继续尝试下一来源，单个来源返回错误 infohash 时也继续核验其他来源。
- Torrent 批量补齐可直接使用搜索列表的 infohash，不再依赖先获取 API 详情；两种批量操作独立运行，文件路径和文件数去重合并。
- 元数据下载遇到损坏、超时或未收录时尝试固定可信来源，始终校验 infohash；拒绝跳转到无关站点。
- 搜索默认只取列表；当前显示页的详情与 Torrent 文件大小改为搜索按钮旁的两个手动批量操作。列表先用 infohash 生成 Magnet，详情到达后换成完整链接。
- 文件路径筛选在未取得详情时显示待核实候选；取得详情后隐藏不匹配结果，不把未知当成已核实命中。
- 增加本地页补齐开关与目标条数；`-1` 关闭，正整数按需续读后续 API 页。
- 结果区分别显示本地页码和来源 API 页范围；返回已组装页面时复用缓存，并避免重复条目。
- API 页失败时中断补齐；手动批量详情和 Torrent 补齐逐条报告失败。
- 顶部 API 额度按同一重置周期已见最低剩余额度显示，刷新页面后保留该值；真实请求后更新，缓存及乱序响应不会让数字回升，同源标签同步显示。批量详情完成提示区分真实请求与缓存。
